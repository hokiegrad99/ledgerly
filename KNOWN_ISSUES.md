## ISSUE-001
- **Title:** Budget rollover carry-forward is stored but not computed
- **Severity:** Medium
- **Status:** FIXED
- **Affected requirement:** REQ-026
- **Steps to reproduce:** Mark a category with "rollover", end a month under budget,
  move to the next month — the unused amount is not added to next month's budget.
- **Expected:** Unused budget with rollover=true carries forward.
- **Actual:** The flag is persisted; carry-forward math is not implemented.
- **Resolution:** Added `budgetRolloverCarryover` (pure function returning the previous
  month's signed remainder per rollover category) and carryover support in `budgetSummary`;
  the Budget page computes carry from the previous month (surplus adds, deficit subtracts),
  shows carried amounts per row, and exposes a per-category rollover toggle. The Dashboard
  budget widget includes carry-forward. Covered by 7 unit tests.

## ISSUE-002
- **Title:** PWA offline behavior verified only at build level
- **Severity:** Medium
- **Status:** VERIFIED
- **Affected requirement:** REQ-041
- **Steps to reproduce:** Deploy to GitHub Pages, install the app, go offline, reload.
- **Expected:** App loads and core functionality works offline.
- **Actual:** Service worker and manifest are generated by `vite-plugin-pwa`; live
  offline verification has not been performed.
- **Resolution:** Deployed to GitHub Pages (2026-09-10). `scripts/verify-deployed.mjs`
  (headless Chrome via CDP) confirmed against the live deployment: manifest served and valid,
  service worker registered/activated and controlling the page, full offline reload renders the
  app with stored data intact, and in-app navigation works offline. No console errors observed.

## ISSUE-003
- **Title:** Transaction search does not search tag names
- **Severity:** Low
- **Status:** FIXED
- **Affected requirement:** REQ-035
- **Steps to reproduce:** Search for a tag name (e.g. "Travel") in Transactions.
- **Expected:** Transactions with that tag appear.
- **Actual:** Search covers merchant/description/notes only; tag filtering is
  available via the tag filter dropdown but not free-text search.
- **Resolution:** `queryTransactions` now resolves tag names → ids once per query
  (case-insensitive contains match on tag names) and a transaction matches free-text
  search when its `tagIds` intersect the hits — OR'd with merchant/description/notes.
  Covered by a new repository test (merchant match, tag match, case-insensitivity).
  REQ-035 marked VERIFIED.

## ISSUE-004
- **Title:** Reports "category" filter select lists every category ungrouped
- **Severity:** Low
- **Status:** FIXED
- **Affected requirement:** REQ-033
- **Steps to reproduce:** Open Reports, open the category filter.
- **Expected:** Categories grouped by group.
- **Actual:** Flat list (functional, less scannable).
- **Resolution:** The Reports category filter now renders `<optgroup>`s per
  non-archived category group (matching the transaction filter), with an "Other"
  group for non-archived categories whose group is archived or missing so nothing
  is silently dropped. Empty groups are omitted.

## ISSUE-005
- **Title:** No undo for bulk delete
- **Severity:** Low
- **Status:** FIXED
- **Affected requirement:** REQ-014
- **Steps to reproduce:** Select many transactions, delete.
- **Expected:** Undo is available where practical.
- **Actual:** Deletion is immediate with a confirm dialog only.
- **Resolution:** `src/domain/undo.ts` captures a snapshot of everything a delete
  removes (transactions, their splits, and any referenced transfer pairs) *before*
  the delete runs, and restores it on demand. The Transactions page holds the
  snapshot in a short-lived (10s) in-memory buffer and shows an "Undo" toast after
  each delete, including singletons from the row menu. The delete confirm dialog now
  states the action is undoable for a few seconds. Covered by unit tests
  (`src/domain/undo.test.ts`).
